# Latam Digest data pipeline

The shipping iOS app uses public static JSON feeds. This pipeline needs Node.js 24 or later and does not need an OpenAI credential.

```sh
npm ci --workspace=@latam-digest/static-feeds --include-workspace-root=false
npm run check --workspace=@latam-digest/static-feeds
npm test --workspace=@latam-digest/static-feeds
npm audit --omit=dev --workspace=@latam-digest/static-feeds --include-workspace-root=false
npm run generate:static --workspace=@latam-digest/static-feeds
npm run check:coverage --workspace=@latam-digest/static-feeds
```

The generator reads Google News RSS and writes `docs/api/countries.json`, `manifest.json`, and country/category feeds. It uses browser-safe URLs, stable article IDs, and atomic file replacements. Invalid publication dates are rejected. Failed or empty upstream responses preserve recent successful data for at most 24 hours; a partially successful refresh retains the original update time and marks those feeds stale. The low-level generator fails if every feed fails. The production command stages output and validates it before replacing the publication; the recovery behavior for provider outages is described below.

RSS requests have a 20-second deadline covering headers and body, with at most three attempts. Network failures, timeouts, HTTP 408/429/5xx, and invalid RSS responses use exponential backoff with jitter. `Retry-After` seconds and dates are honored; a delay over 60 seconds ends that request instead of retrying too soon. Permanent HTTP failures and valid empty feeds are not retried. Five consecutive exhausted Google requests stop further Google requests during that generation; independent publisher recovery continues. Empty feeds do not count toward that circuit breaker. The generator also has a 20-minute overall deadline and the Actions generation step has a 22-minute backstop inside the 30-minute job.

Diagnostics report a controlled failure category, HTTP status where available, attempt count, and a final refresh count. Response bodies, request URLs, headers, and raw provider exceptions are never logged or written to public feed metadata. Provider outages never publish old data as fresh. The production recovery wrapper can retain a complete verified publication while explicitly reporting degraded health.

## Provider outage recovery

Every production country/category feed has an independent publisher fallback. `src/publisherSources.js` covers all 24 countries and all ten categories (240 feeds), with reviewed national RSS endpoints, publisher-owned article archives, bounded pagination and additional regional publishers. Specific section feeds remain available for TT/politics, GF/economy and GF/world. All other categories use the same national and regional pools; a publisher's location or section never substitutes for country/category evidence in the headline.

When Google returns too few eligible stories or a request fails, the generator tries those publishers. Recovery seeks three eligible stories from at least two distinct publishers before stopping; multiple sections of the same publisher do not count as independence. If the bounded inventory supplies fewer, valid sparse feeds remain supported. After five consecutive exhausted Google requests, it stops asking Google for the rest of that generation and continues independent recovery across the entire matrix. Each publisher RSS response, including a failure, is reused only within that generation, across categories; the next generation fetches it again. Requests run in batches of at most three, with eight-second per-attempt timeouts and the overall twenty-minute refresh deadline. RSS retains its three-attempt limit; publisher archives use at most two attempts and do not immediately retry responses with Retry-After. Successful primary requests reset the failure streak.

Short RSS lists no longer define the entire fallback inventory. Reviewed WordPress archives provide up to eight 100-article pages from the recent publication window; Outremers360 supplies a bounded public article archive. Regional archive searches stay country-scoped. Pagination follows only configured endpoints, never arbitrary response URLs. Discovery results and failures are shared across categories only during one generation; a later generation fetches them again. No API keys or Google services are required for publisher recovery.

Reviewed publisher-owned news sitemaps also supply candidates. Their news namespace, exact article hosts and explicit publication instants are checked; sitemap `lastmod` is never used as an article date, and sitemap indexes are not followed dynamically. Péyi Guyane's rendered headline cards and most-read news list supply discovery where RSS is unavailable. Those links receive dates only after verification on the original article page. Neither mechanism bypasses original-page, country/category, URL or freshness checks.

Run `node scripts/audit-publisher-coverage.mjs --output /tmp/publisher-readiness.json` from `backend` to check all 240 feeds using independent publishers only, without Google or a publication cache. The bounded audit reports empty feeds, publisher diversity, article counts and original-date expiry headroom. Its diagnostic target is three stories and two publishers each supplying a story with at least 48 hours before the thirteen-day publication cutoff. This research target does not change the publication gates or reject legitimate sparse feeds. The command does not publish or dispatch workflows and is not a second catch-up controller. Availability is measured at audit time, not guaranteed for future outages.

Guyane's pool also includes KARIBINFO's country-scoped archive for all ten categories. EU funding qualifies for World only with explicit public-programme or territorial-governance evidence, in addition to national relevance; a generic European investment fund does not qualify. The aging-singleton regression exercises both an empty Google result and HTTP 503, verifies the original publisher date, and recovers with a 49-hour-old unusable cache. This guards the reproduced gap without extending article or cache lifetimes.

GF/world additionally checks Université de Guyane's original reporting on international cooperation through its publisher archive and RSS. These two transports count as one publisher; courses, jobs and student elections do not establish foreign affairs. RFI's Guyane RSS supplies another national discovery route. Brazil also checks BBC News Brasil, CNN Brasil's publisher archive and Poder360; Ecuador checks Primicias's publisher-owned news sitemap. MercoPress country feeds for Argentina, Brazil, Chile, Paraguay, Uruguay and Venezuela retain country stories that can disappear from its short general feed. All use the same article and publication validation.

MercoPress's reviewed English article template gives its original publication minute in UTC immediately under the exact article headline. The original-date reader accepts only that host and structure, validates the calendar date and weekday, and rejects conflicting dates. The site's live Montevideo clock and recommended-story dates are never publication evidence. Explicit CPTPP accession qualifies as international treaty affairs; a bare acronym, merchandise or a training course does not.

Publisher articles must have matching headline evidence and an unambiguous original publication instant on the actual publisher page (published metadata or Article/NewsArticle JSON-LD, including a WebPage's explicit mainEntity). A matching metadata headline may append an exact reviewed publisher/site credit. Fractional and whole-second versions of the same publication second retain the earliest stated value; genuinely conflicting dates still fail. RSS update times are replaced only by that verified original instant; inaccessible, ambiguous or undated pages cannot supply fallback articles. Public publisher requests use Node's HTTPS transport with TLS verification, cancellation and a streaming 2 MB body limit. Page requests are reused within the generation, use five-second timeouts and follow at most four exact-host HTTPS redirects. Articles must also have exact allowlisted HTTPS article hosts, safe URLs, stable IDs, independent country/category evidence and the same thirteen-day publication age limit. Feed build dates, modification times and retrieval time never replace missing article dates. Existing source quarantines and semantic exclusions apply equally to publisher recovery and cache recovery.

If no eligible fresh result exists, the existing cache may be retained only within its original 24-hour limit and with every article still satisfying the 24-hour publication margin before the fourteen-day hard age bound. Cached feeds keep their original update times and are explicitly marked stale/degraded. Freshly fetched feeds receive new refresh metadata. If a required feed is empty, expired, unsafe or otherwise invalid, atomic validation blocks the candidate and preserves the previous publication. French Guiana World alone can publish as temporarily unavailable when it has no eligible articles or usable cache. Its empty list is explicit, carries no refresh timestamp, and is counted separately from fresh and cached feeds. Each refresh still tries to repopulate it. Independent sources reduce dependence on Google; they cannot guarantee that every subject has current news or that all providers will remain available.

A total primary failure can still receive one bounded full retry and a final independent-publisher/cache recovery attempt. Programming errors, invalid output and nonretryable provider errors are not silently waived. `refresh-status.json`, the manifest, workflow logs and hosted verification report the actual fresh/cache counts. GitHub notification settings are unchanged.

Regression tests cover all 240 fallback routes, empty results and HTTP 503s, bounded primary requests, publisher request reuse and failover, original dates and stable IDs, wrong-country/category/host results, cache expiry, cancellation and atomic validation. Fixture-based whole-provider outages must successfully publish all 240 independently supplied feeds, including an archive-only recovery with every prior cache 49 hours old. Tests also cover malformed archives, bounded pagination, original-page date conflicts, unsafe redirects and cancellation. Live checks separately record how many feeds currently have eligible publisher articles; configured fallback coverage is not a claim of guaranteed current article availability.

## Country and category coverage

All 24 countries have ten feed definitions. Searches use Spanish, Brazilian Portuguese, French, Dutch (Suriname), or English with local country names and category vocabulary. `Latest` searches for recent reporting rather than requiring the literal English words “latest news”. This fixes the six empty queries observed on October 18: Dominican Republic/economy, Nicaragua/economy, and French Guiana/latest, culture, economy, and world. Direct RSS probes found 0 results for each old query; localized economy queries returned 81 results for the Dominican Republic and 71 for Nicaragua.

A feed with fewer than three relevant articles expands its search from 3 to 7 days for headlines, or 7 to 14 days for categories. A final English-language search uses the same country and category when needed. Queries use at most six topical alternatives; overly long OR expressions returned mostly historical matches in live probes, so publication dates are checked independently. Trinidad and Tobago searches include both island names and recognize the local abbreviation “T&T”. Searches never substitute another country or general news for a category. Articles must have a country/place/demonym and category vocabulary in the headline, a safe URL, and a publication date within the chosen window. These are conservative keyword relevance checks, not a semantic classifier. French Guiana recognizes local place names and excludes Porsche Cayenne name collisions. All candidates are deduplicated by URL identity and headline/source, then sorted before taking the newest twelve. RSS text remains text, including numeric publisher names such as `442`.

The manifest records search languages, lookback window, fallback use, and aggregate coverage counts. Publication dates are never rewritten to make older stories appear new. Cached fallback keeps the original refresh timestamp, is retained for at most 24 hours in both partial and full outage recovery, and also excludes stories older than thirteen days or failing the same relevance checks. The reader validation limit remains fourteen days, leaving 24 hours of safety between publication and expiration. Small news markets may legitimately have only one or two matching stories; those are reported as sparse rather than padded with unrelated headlines.

`npm run check:coverage` verifies the complete country/category matrix and every feed file before Actions can commit. Missing feeds, unmarked empty feeds, mismatched counts, duplicate IDs, unsafe URLs, expired timestamps, and articles failing headline/date checks block publication. Recent cache use and sparse feeds produce visible workflow warnings. Regression tests cover localized and expanded searches, English fallback, wrong-country/category results, numeric publishers, date limits, deduplication, and coverage verification.

The GitHub Actions job runs on demand and every six hours, serializes overlapping runs, and validates dependencies and tests before generating feeds. Static data is served from this repository; publisher links may pass through Google News redirects.

### October 18, 2026 incident

[Run 39142145369](https://github.com/apovolotski/LatamDigest/actions/runs/39142145369) passed dependency installation, syntax checks, all six existing tests, and the audit. Every one of its 240 feed refreshes failed; the generator then explicitly exited with `All RSS requests failed; do not publish this refresh.` Publication was skipped. It was not a job timeout or a Git push permission error. [Run 39164132148](https://github.com/apovolotski/LatamDigest/actions/runs/39164132148) subsequently succeeded from the same source revision, refreshing 234 feeds.

The old generator tried each request once and discarded every underlying exception, including HTTP status, network errors, and invalid-response errors. The historical log therefore cannot establish which specific upstream condition caused that run-wide failure. The fix addresses this confirmed handling defect with bounded recovery, early termination during sustained failure, preserved publications, and safe diagnostics that distinguish the conditions on future runs.

### October 23 dependency audit incident

[Run 40026114377](https://github.com/apovolotski/LatamDigest/actions/runs/40026114377) passed all 147 tests, then stopped at `npm audit` before feed generation. The newly reviewed [Zod advisory GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) affects versions below 4.6.6. The optional AI worker used Zod 3, and its older OpenAI SDK required that major version. The dependency audit correctly blocked the job; this was separate from RSS availability or language matching, and no publication was attempted.

The backend now requires Zod 4.6.7 or newer and a compatible OpenAI SDK 6. The AI worker limits response arrays to ten stories before item validation. Regression tests use the actual SDK with a simulated transport to cover normal synthesis, truncated JSON recovery, malformed and oversized arrays, compact retries and sparse windows without credentials or paid requests. The lockfile and blocking dependency audit remain part of the workflow; future advisories may still require another tested dependency update.

### Separate feed and optional backend dependencies

Manual reproduction [40059808308](https://github.com/apovolotski/LatamDigest/actions/runs/40059808308) exposed another newly reported advisory, [GHSA-27r3-jxmh-p828](https://github.com/advisories/GHSA-27r3-jxmh-p828), in Express's body-parser 1.20.8. All 151 tests passed before the audit blocked generation. The lockfile now uses patched body-parser 1.20.9.

The underlying coupling is also removed: the static publisher installs only the `@latam-digest/static-feeds` workspace and its RSS parser dependencies. Its clean-install check fails if optional Express/AI packages are present. All 145 feed tests, the workspace dependency audit, and all publication/recovery checks remain mandatory. A separate **Backend Checks** workflow runs the complete 161-test suite and full dependency audit on backend pushes, pull requests and daily; it also tests a clean feed-only install. No tests were discarded: optional server/AI and maintenance tests live in `test/optional/` and run in that complete suite. Dependabot checks for compatible npm updates daily; unsolicited major-version proposals are excluded.

The regression scenario was verified with body-parser 1.20.8 restored only in a disposable lockfile: the full backend audit correctly failed while the isolated feed audit remained clean and the unused server packages were absent. An accidental full install is independently rejected by `check-static-dependencies.mjs`. This keeps server advisories visible in the server checks without stopping a feed job that neither installs nor executes that code. Advisories affecting the RSS runtime still block publication and require repair.

### October 28 security maintenance incident

[Run 40729599050](https://github.com/apovolotski/LatamDigest/actions/runs/40729599050) passed all 151 existing backend tests and the isolated RSS job. Its full audit found [GHSA-6pq8-jhm2-2vcw](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw) in locked qs 6.16.0, which can throw on hostile objects during comma-array serialization. The news workflow continued succeeding. The qs override now requires at least patched 6.16.1 and the lockfile uses 6.17.0; a regression covers both comma encoding paths and normal query behavior.

Dependabot proposals alone did not apply fixes to main. Scheduled and on-demand Backend Checks on main now run `npm run maintain:security` before installation. It uses `npm audit fix --package-lock-only --ignore-scripts` without `--force`, preserves manifests and workspace declarations, rejects downgrades and breaking version changes, and requires a clean audit. A failed or unverifiable repair restores the original lockfile. Dependency lifecycle scripts are disabled in backend validation installs.

The exact candidate is hashed and passed as an immutable workflow artifact from the full 161-test job to the isolated 145-test RSS job. Only after both jobs and both audits succeed may a separate job with write permission publish that lockfile. Test jobs retain read-only credentials. Publication verifies the artifact hash and refuses to overwrite concurrent backend changes; unrelated feed-data commits are preserved. Normal push/PR checks do not repair or publish dependencies.

`verify_maintenance=true` on a manual main-branch run exercises the complete repair/artifact/publish path using vulnerable qs metadata only. The unsafe version is repaired before installation, never installed or published. A main lockfile that already matches the fully validated candidate needs no commit. Local regression checks also cover unfixable/transport-error audits, manifest mutation, breaking upgrades, artifact tampering and concurrent backend changes. An incompatible fix, unavailable registry or failing test remains a visible failure requiring investigation; checks and notifications are not suppressed.

## Hosted maintenance

**Hosted Maintenance** runs on GitHub-hosted Ubuntu runners every hour and after either monitored workflow completes on trusted main. It works while the owner's computer is asleep or Codex is closed. It uses the repository-scoped Actions token; no personal access token, OpenAI key, external account or local process is required. The native six-hour feed schedule and daily backend schedule remain unchanged. GitHub can delay scheduled events, including the monitor itself; completion events provide a second trigger, not a guarantee of exact-time delivery or independence from a GitHub-wide outage.

The controller reads complete job logs and all annotations for new runs, checks both production audits and dependency isolation, and validates each exact feed publication using its matching source. Every check independently validates the current 240-feed snapshot, original article dates, 24-hour feed/cache limits, truthful health, and all 243 app-facing JSON responses. Cached recovery and sparse feeds follow the existing strict publication rules. A publication advancing during inspection is checked on the next completion/tick instead of being mistaken for corrupted old data.

Audit verification reads the original per-job files from the exact run attempt's log archive and checks the audit step's actual successful result. It does not depend on the display labels in `gh run view`, which can become `UNKNOWN STEP`. A clean installation cannot replace a production audit, and missing, failed or skipped audits remain invalid. Parser upgrades re-inspect earlier invalid results while retaining their original evidence and incident history; they do not silently waive failed checks or discard milestone progress.

GitHub also returned completely empty `steps` arrays for successful jobs in run 41104929285. In that case the controller verifies the original executed command, its actual output, the successful job, the fail-fast shell and a reviewed SHA-256 contract for the workflow at that run's exact source commit. Both current workflow contracts have blocking tests/audits and no `continue-on-error`. Workflow edits must pass the contract regression before this alternate proof is allowed. The report identifies this evidence source explicitly without inventing step numbers. Explicit failure/skipped metadata, missing or ambiguous command output, unreviewed workflow source and non-blocking shells remain invalid. Feed generation times use the original command's timestamp bounds when step metadata is unavailable.

Test verification requires at least the retained 161 backend and 145 isolated feed tests, allowing new passing regressions to increase those totals. Each complete summary must belong to its own successful test command and original job, with zero failed, cancelled, skipped or todo tests. The isolated dependency guard must also pass in the RSS job. A controller suite, another job's totals, duplicate summaries or text echoed in a command header cannot substitute for that evidence. This prevents an exact-count check from reporting a false failure when the test suite grows.

Catch-ups require a 90-minute schedule grace period and, for feeds, at least 7.5 hours without a validated refresh or expiry before the next hourly check. A failed run or invalid data can receive one bounded recovery. Backend catch-ups also run the existing compatible security-maintenance path. Active runs prevent duplicate dispatches. Reservations are committed before dispatch; uncertain requests are never blindly repeated. Feed and backend catch-ups have six-hour and 24-hour cooldowns. A manual `exercise_dispatch=true` proves the real GitHub-token dispatch path for both workflows without weakening validation or changing timestamps.

Recovery receipts distinguish an unconfirmed dispatch from an unresolved service problem. An unmatched reservation can be marked `superseded` only by a later, fully verified successful run of the same workflow. Feed recovery additionally requires that run's exact publication to be current, fresh, outside the expiry safety window and byte-matched at all 243 app-facing URLs. A superseded receipt preserves its original key/time, previous status and uncertain dispatch outcome, and separately records the replacement run; it never invents a successful bot dispatch. Its original cooldown and once-per-key protection remain in force. Active/newer failed runs, invalid publications, unverified evidence, explicit dispatch probes and known nontransient access rejection cannot use this resolution. Late exact confirmation is recorded separately without erasing the recovery history. The controller stores only sanitized HTTP error classification, never provider response bodies or credentials.

Inspection version 6 retains the verified publication commit in each feed inspection. Earlier valid feed evidence without that identity is re-read from its original attempt archive, preserving prior verification history. Durable receipt, inspection and milestone history is not deleted when Actions artifacts reach their separate retention limit; large ledgers use the exact Git blob reader and compare-and-swap writes.

The public `latam-monitor-state` branch holds a sanitized, compare-and-swap ledger at `monitor/state.json`: run identities, milestones, receipts, health and evidence hashes. It contains no Mac paths, credentials or local conversation history. The first four scheduled successes of each workflow remain a milestone; monitoring continues afterward. Manual catch-ups do not count. Detailed evidence is retained as Actions artifacts for 30 days, with original run logs under the existing GitHub retention policy. Routine success/recovery does not create issues, email messages or comments. A newly unresolved incident surfaces as a failed monitor run through the existing GitHub notification settings, and the same incident is deduplicated in the ledger. Incompatible dependency fixes and new source-code bugs still require validated investigation; the hosted controller does not invent code patches or bypass security checks.

The write-capable completion trigger excludes forks and pull requests and always checks out trusted main. Dependency installation and tests run before the controller receives its token. Only the existing workflows can be dispatched. Controller tests cover clock boundaries, cache expiry, fork/PR exclusion, deduplication, cooldowns, durable reservations, uncertain writes, concurrent run races and persistent state. To stop hosted maintenance, disable **Hosted Maintenance** itself; while enabled it can re-enable the two existing native workflows if their schedules are disabled.

## Optional AI worker

Run `npm ci`, `npm run check`, `npm test` and `npm audit --omit=dev` from `backend/` for the complete optional backend installation and validation. `npm start` serves the legacy cached-digest API. Its public routes cannot trigger AI generation or use `?refresh=true`. Empty caches return 503. AI generation runs only on the configured cron schedule when `OPENAI_API_KEY` exists on the server; the first scheduled run warms the cache. Concurrent refreshes coalesce into a single provider request, and failures keep the prior digest.

The app's default static pipeline does not use this worker. Deploying it requires separately configuring the host, a fresh server-only secret, quotas, monitoring, and the intended feed URL. These are not configured by the source changes alone. Do not restore or reuse the key exposed in the earlier conversation. Never send it to iOS or commit `.env` files.


### Publication age rollover regression

The first monitored scheduled recovery (run 39333988284) correctly preserved the cache on October 19. A Suriname sports article dated October 6 at 00:30:28 UTC was within fourteen days when the job published at 22:23 UTC, but expired before the next scheduled run. Validation at October 20 00:51 UTC reproduced this time-dependent failure. Publication now filters fresh results and retained cache to thirteen days and independently enforces the 24-hour margin before promotion. Expired and soon-expiring removal counts are reported separately. Regression tests advance validation by a full day, verify source timestamps remain unchanged, and reject newly generated candidates lacking the margin.
